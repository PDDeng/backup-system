## Nexus：把连接恢复与复制优化分开

### 当前可确定与不可确定的结论

- 有一份可独立复核的7734.6秒失败结果；“连续8次”来自前序协调审计，尚未逐条取得8次源端日志，本交付不将次数写成已独立验证。
- 仓库 CopyTree 对 work 预复制硬编码7200秒、application 3600秒，停止后最终同步预算240秒；总耗时还包含扫描与其他阶段，不能用7734.6直接当成纯传输时间。
- 46万级小文件会受到遍历、SMB元数据与磁盘时延影响。当前没有失败批次的完整Robocopy统计，不足以认定带宽、CPU或NAS是唯一根因。
- 活跃预复制不是一致性备份，锁文件错误不可简单忽略后发布；必须在停写后的最终同步与清单检查通过后才发布正式回执。

### 取得管理通道后的最小只读检查

1. 读取生产 worker 与 config 的 SHA256、任务动作、服务状态、当前进程和最新 last-result。以实际版本为准，不能把仓库旧版覆盖上去。
2. 收集失败批次 Robocopy 日志尾部：源/目的、阶段、复制文件数/字节、跳过与失败数、退出码、耗时、锁定文件以及是否仍有数据增长。确认任务互斥是否有效。
3. 核查是否停在预复制，是否曾进入停止服务阶段，恢复看门狗是否存在且实际服务 Running。对超时后的恢复动作单独验收。
4. 不启动第二个扫描/复制。先利用已有日志计算吞吐和元数据速率；NAS检查限已挂载共享的连接和容量，不新建大负载测试。

### 候选优化，需独立审核后另行获准实施

- 把预复制、应用目录和停机最终同步预算拆为显式配置，并增加阶段名、最近进度时间、文件与字节计数。区分硬截止与无进度超时；外部任务调度总期限必须覆盖所有阶段。
- 首次大副本使用人工批准的初始化窗口。后续可从已发布且验证过的不可变副本建立受控 staging，再做增量同步；不得直接修改历史完整副本。
- 如需复用失败 staging，先定义同资产/同源/版本所有权、互斥与恢复协议；没有这些校验时继续使用唯一 partial，不直接续传未知目录。
- 预复制阶段可研究只豁免明确的运行锁文件；最终停止同步仍须复制必要数据库并验证全量清单。锁文件豁免不能扩展成“所有复制错误忽略”。
- Robocopy /MT仅作为测量后的候选，先低并发4，比较NAS延迟与业务影响；不默认32线程，不使用 /256，不放宽长路径支持，不将 /MIR 指向正式副本。
- 当前240秒最终窗口是否足够必须实测；若遍历本身超预算，结束并恢复服务，维持失败/未发布状态。扩大停机窗口需单独审批，不能为绿色结果延长停服。
- 主副本发布并恢复服务后再分发240/254，二级目标失败只重试分发，不能重启源端备份；各端结果独立，不清除已有成功端记录。

验收：至少一次完整副本发布、三端清单与所选完整性策略通过、失败注入后看门狗恢复、无后台复制遗留、停机实际时长在批准窗口内。实际恢复验证仍是单独任务。

## SVN29：分层定位 WinRM 挂起

先用 NAS 上已有正式回执核实最近有效批次；11月19日旧副本/恢复演练不能证明今天任务成功。采集失败在页面标为“源端结果未知／最近副本过期”，不要替换成“今天备份失败”。

源机管理员可逐条执行以下只读命令，每条单独提交，不粘贴成无分隔长串：

```powershell
Get-Service WinRM
winrm enumerate winrm/config/listener
netstat -ano | findstr ":5985"
Get-WinEvent -LogName Microsoft-Windows-WinRM/Operational -MaxEvents 20
Get-WmiObject Win32_Process -Filter "Name='wsmprovhost.exe'" | Select-Object ProcessId,CreationDate
```

诊断顺序：TCP -> HTTP/WSMan响应 -> NTLM协商与加密 -> hostname短命令 -> 任务元数据。每层独立记录时间和错误类型，不把HTTP401当成认证通过，不把命令启动当成完成。

- HTTP层无响应：在源机同步查看 WinRM 事件、HTTP.sys监听与进程资源；由网络/主机管理员检查丢包和过滤，不以关闭防火墙或TrustedHosts星号“修复”。
- 协商后重置：对齐服务器与客户端事件时间，检查安全软件/协议兼容/配额；不得全局降低TLS或NTLM安全要求。
- 短命令成功而长任务挂起：备份由本地任务调度执行，WinRM只查询状态，禁止让120GiB复制依赖一个长远程会话存活。
- 存在活动hotcopy/verify时只观察，不重跑。取得新批次后核实12个仓库UUID、修订号与 svnadmin verify，再发布；失败保留partial，不删除旧副本。
