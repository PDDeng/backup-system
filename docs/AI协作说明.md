# AI 协作：一主一副，可增减员工

主负责人暂定 Codex，副负责人 Gemini。主负责人可工作时统一分配任务；主负责人额度不足或明确交接时，Gemini 按相同规则接管。

已登记员工 OpenCode（id：opencode-worker），启用参与任务分配，主要负责后端与测试，允许修改 platform/ 和 tests/。模型显示名称按用户提供记录为 claude haiku 5.5；实际调用的 provider_model_id 尚未填写，需以 OpenCode 中可用模型的准确标识为准。启用登记不表示已建立工具连接；会话入口和独立工作目录仍需填写。

**本版是协作协议和配置模板，不是已运行的多 AI 自动调度程序。** 不同工具的聊天不会自动互通，配置文件也不能让 Gemini 自动收到消息。当前由你复制交接提示给对应会话；以后接入工具的 API 或 CLI 适配器后才能自动触发。不能保证不同模型输出质量完全相同，但可以用相同验收门槛阻止未经验证的结果上线。

## 需要填什么

复制 config/ai-team.example.json 为 config/ai-team.local.json，在本地填写：

| 配置 | 填写内容 |
| --- | --- |
| human_owner / human_contact | 你或项目负责人的姓名、联系渠道 |
| tool / model | 每个员工实际使用的工具与模型 |
| contact_or_session | 该 AI 会话链接或任务入口 |
| workspace / branch_prefix | 独立工作目录与分支前缀 |
| skills / allowed_paths | 擅长工作及允许修改的目录 |
| enabled | 是否参与调度；新增员工复制一项，id 保持唯一 |
| adapter | 当前保留 manual；自动化时由开发者填写已验证的命令和凭证环境变量名 |

API Key、服务器密码不填入配置。凭证只放本地环境变量或凭证库。停用员工前先交接其任务，不能直接丢弃未提交代码。

## 平时怎么用

1. 当前负责人把任务写入 coordination/tasks.json 的 tasks，每项明确负责人、独立审核人、验收标准和验证命令。
2. 员工使用自己的分支和工作目录，按允许范围修改；完成后提交代码和测试证据。
3. 独立审核人检查差异、测试和边界条件。失败就退回，不以“已经运行”代替验收。
4. 负责人协调合并。生产操作仍遵循既有授权；接管不会扩大权限。

## Codex 额度不足时

如果能提前交接，Codex 先补齐 coordination/HANDOFF.md 并提交。若突然中断，Gemini 先检查 Git 状态、任务记录、实际后台任务和日志，不能假设上一步失败，也不能直接重跑长备份。

你给 Gemini 发送：

> 请接管 backup-system 副负责人工作。先阅读 AGENTS.md、config/ai-team.example.json、docs/HANDOFF.md、coordination 下的任务与交接记录，核对最新提交和实际运行任务。列出证据与不确定项，确认原负责人不再并发操作后，记录接管时间并递增 state.json 的 epoch。按原有验收门槛继续分配任务；不得降低测试要求，不得批准自己编写的改动，没有独立审核人时保留待审，不合并或部署。不重复运行尚在执行的备份，不扩大生产授权。

仅心跳超时不允许接管，避免网络中断造成两个领导同时写生产。当前手工模式下，你确认交接后再修改 active_leader；state.json 只是记录，真正自动调度需要外部调度器提供原子锁、心跳、超时隔离和过期领导拒写机制。

## Gemini 接管后的质量底线

- 每项任务有可检验的完成标准；代码作者与审核人不同。
- 真实数据与示例数据分开；未知状态不能变成绿色成功。
- 测试失败、缺证据或生产版本不明，阻止合并及部署。
- 变更前记录生产版本、授权范围和回滚方法。
- 无审核员工在线时，可以继续开发和测试，保持待审；等你或其他独立审核者确认。
- Codex 恢复后先复核交接记录，通过明确交接重新成为负责人，不抢占 Gemini 正在执行的生产操作。

## 自动化后续范围

需要另外实现：各工具的调用适配器、额度/可用性探测、任务队列、原子领导锁、审查门禁及审计日志。不要仅把 automatic_takeover_enabled 改成 true 就认为自动接管已生效。
