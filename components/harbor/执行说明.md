# Harbor首份NAS备份：由ops253收集

248不必安装cifs-utils，不在248或ops根盘存185G整份副本。ops使用已有/mnt/core243、core240、core254。目录：资源备份/harbor01_10.10.11.248_镜像仓库/日期/运行号。

## 1. 上传包到ops253

把harbor-ops-first.zip放到/home/ops，root执行：

```bash
mkdir -p /opt/harbor-backup
unzip /home/ops/harbor-ops-first.zip -d /opt/harbor-backup
install -m 600 /opt/harbor-backup/harbor248.json /etc/core-backup-ops/harbor248.json
ssh-copy-id -i /opt/core-backup-ops/ssh/id_ed25519.pub -o UserKnownHostsFile=/opt/core-backup-ops/ssh/known_hosts root@10.10.11.248
```

第一次对照248控制台主机指纹，不能绕过known_hosts检查。已有同名配置先备份，不在运行中覆盖。配置名harbor248.json不会被GitLab整批脚本自动发现。

## 2. Harbor248本机准备API凭证

在248的root终端，用编辑器创建/root/.harbor-backup.netrc：

```text
machine 127.0.0.1
login admin
password 填写Harbor管理员密码
```

这是Harbor管理密码，不是NAS或Linux密码；不要把实际值发聊天。netrc特殊字符须遵循本机curl支持的netrc格式，如密码含空白或特殊引号应先验证解析，不随意拼入命令行。文件权限：

```bash
chmod 600 /root/.harbor-backup.netrc
```

本脚本API只GET配置，不自动更改设置，不打印完整配置响应。API经SSH在248本机回环HTTP访问，不从ops网络明文发送管理员凭证。

## 3. 打开只读并暂停后台写入

Harbor网页Administration→Configuration→System Settings→Repository Read Only保存。记录原状态。暂停计划中的复制写入、保留清理和GC，等待已有push/delete/GC/复制写入结束。不要停止拉取服务，不执行docker compose down。

仅开启只读不是所有后台写入已停止的证明，脚本--writers-quiesced参数代表操作员已完成上述确认。没有完成不要带此参数启动。

## 4. ops检查

```bash
python3 -u /opt/harbor-backup/harbor-backup.py --check
```

必须检查通过。它严格检查SSH、API只读、DB就绪、挂载范围、三个NAS真实挂载/写读删和容量。NAS容量检测基于整个部署目录大小保守预估。检测出外置挂载则拒绝，先明确备份范围。

## 5. 正式备份

确认无后台写入后，ops执行：

```bash
nohup python3 -u /opt/harbor-backup/harbor-backup.py --writers-quiesced >> /var/log/harbor-backup.log 2>&1 < /dev/null &
tail -F /var/log/harbor-backup.log
```

生成：database.sql（harbor-db容器内部pg_dumpall逻辑导出）、registry.tar（镜像仓库，排除未完成_uploads）、configuration.tar（部署目录配置/证书/密钥；排除活动PGDATA、Redis、仓库重复数据、运行日志）、backup-result.json。独立postgres容器不在此范围。

SSH流直接写NAS243的.partial，成功关闭文件并fsync、检查大小和源端返回码后才发布。此版本不做MD5、不做完整tar读取验证，不宣称已演练恢复。SQL及密钥敏感，NAS权限限制为备份账号和管理员。

看到Webhook“Harbor source collection complete on nas243”后，可恢复原来的只读/后台任务设置；后面240/254从NAS243复制，不再依赖Harbor保持只读。若源端收集失败，查看失败告警并人工决定结束窗口、恢复原状态，脚本不会擅自改变Harbor配置。

没有自动写入状态恢复，是因为本版没有自动设置原状态或持久保存原设置；不能把这个首份脚本直接挂无人值守cron。进程被强杀/主机失联也无法保证通知送达。

## 6. 验收与后续

```bash
cat /var/lib/core-backup-ops/harbor248/last-result.json
```

三个targets都true才是三端完成。逐端打开UNC的同run目录。失败.partial不算成功，保留排查。当前没有自动重试旧run，也不自动清理Harbor历史。每周日03:00及最近3份成功保留，需要在首份验收后增加写入状态保存/恢复、后台任务排空检查和清理审计，不要直接套用GitLab清理器。

恢复时应在隔离同版本环境验证数据库、registry和密钥对应，不在生产覆盖。拉取计数/Redis登录会话不承诺完整恢复。
