# Nexus51每日03:00直接备份NAS

主机SERVER-51，10.10.10.51；Nexus2.14.11-01；服务nexus-webapp。243、254和240三端，不写本机整份备份。

## 首次安装

将包内文件全部放到51的C:\core-backup\nexus-direct。配置检查nexus-config.ps1：Home、Work、Primary、Secondary、Tertiary，KeepDates默认15。

管理员PowerShell逐条执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\core-backup\nexus-direct\install-nexus.ps1
```

会分别询问NAS243、Windows254和NAS240的SMB账号密码。不是Windows登录密码。凭证用本机DPAPI加密，保存到C:\ProgramData\CoreNexusBackup，仅SYSTEM和管理员权限；本机管理员仍可解密，因此不能对外复制此目录。包内不含真实凭证。

安装不会开始全量备份或停止服务，创建每天03:00的任务CoreBackup-Nexus51但默认禁用，并立即运行独立SYSTEM环境检查CoreBackup-Nexus51-Check。不要使用EnableSchedule参数跳过首次验收。

查看检查结果：

```powershell
Get-Content C:\ProgramData\CoreNexusBackup\logs\*.log | Select-Object -Last 50
schtasks.exe /Query /TN CoreBackup-Nexus51-Check /V /FO LIST
```

需看到CHECK_OK，且计划任务最近结果0。检查会扫描文件元数据和三个共享的读写及容量，需要一点时间；不停止Nexus。若检测到自定义localStorage或目录联接则拒绝，先核对外置仓库范围，不能强行绕过。

检查通过后启用每日03:00：

```powershell
schtasks.exe /Change /TN CoreBackup-Nexus51 /ENABLE
```

当前服务器日期为2026-11-19时，首次计划时间为11月20日03:00；使用本机时间，需确认时区Asia/Shanghai对应的中国标准时间。查询：

```powershell
tzutil.exe /g
schtasks.exe /Query /TN CoreBackup-Nexus51 /V /FO LIST
```

不需在ops上再建同一个Nexus备份任务。此Windows适配器尚未接入GitLab网页。

## 执行过程与业务影响

1. 原服务和HTTP状态必须健康；原本不健康则拒绝，不擅自启动原本停用的业务。
2. 检查源目录、外部存储声明、目标容量及读写，扫描目录不存整份本地副本。
3. 在线预复制到243唯一.partial目录。此时不暂停业务，但此副本不是完整备份。
4. 注册独立SYSTEM一次性恢复任务，然后停止nexus-webapp。
5. 在最多约4分钟的停止复制预算内做最终同步。/MIR仅限本次唯一.partial中的work/application，用于清理预复制阶段已消失的目标文件，绝不对源目录运行。
6. 成功与否都尝试恢复服务，HTTP状态STARTED后记录停机时间。额外8分钟恢复任务会尝试启动服务，防止主脚本异常中断。恢复仍可能失败，必须监控CRITICAL；不是零风险或绝对时间保证。
7. 源服务恢复后才把243正式副本复制到254。检查文件存在和大小，不做MD5。首次预复制可能较长，但不要求全程停服。
8. 三端均成功后按各端最近15个完整日期清理，缺日期向前补足、不足15不删。只删除具有本工具本地归属回执的指定文件及空目录；未知文件阻断清理。保留审计日志。删除不等于可回滚，回滚依赖快照/另一副本。

若最终同步4分钟无法完成，失败保留partial并恢复服务，不无限延长停机。不要反复立即重试；看日志和数据量后安排更合适窗口。

## 结果位置

```text
\\10.10.11.243\资源备份\nexus01_10.10.10.51_maven制品库\日期\运行号\
\\10.10.10.254\资源备份\nexus01_10.10.10.51_maven制品库\日期\运行号\
```

正式目录有work、application、backup-result.json。仅完整停机同步并恢复服务后，243才发布。254复制失败可能243已成功，以日志分别核实；本版失败报告不伪造双端成功，也不自动续传旧run。

日志C:\ProgramData\CoreNexusBackup\logs；最后结果last-result.json；凭证nas243.dpapi/win254.dpapi不要发送。复制凭证配置前备份生产设置，不要在运行中更新脚本。

告警沿用C:\core-backup\notify.json，Enabled=true才通知；机器人TLS/网络失败记录NOTIFY_FAILED，需看本地日志。源脚本不会把真实Webhook贴入日志。长期运行应配置日志轮转和独立漏备监测，本包尚未实现。

## 手动恢复服务

只在服务非正常停用时使用管理员终端：

```powershell
Start-Service nexus-webapp
Get-Service nexus-webapp
```

再打开http://10.10.10.51:8081/nexus/验证。若仍失败，保留日志，不清理源work目录。恢复任务本身不备份、不删除文件。

## 已做验证与限制

本地做语法与辅助C#编译检查；没有对生产Nexus执行停服演练。NAS挂载、SYSTEM身份、实际HTTP状态和运行时间需首次检查及首次计划任务验收。数据目录和程序目录覆盖默认布局；检测到非默认外置存储会阻断，不宣称自动支持所有插件。恢复演练应使用隔离机器同版本，不在生产直接覆盖。
